## Parts the protocol leaves open (recorded as interpretations in the amendment, no new threshold)
1. Gate precedence: `success` if all its conditions hold; else `against` if its condition holds; else `inconclusive` (the residual, including the named inconclusive conditions). Success and against cannot both hold.
2. "Stability Jaccard >= 0.4" is read as arm C's value; B's is reported alongside.
3. Recall, precision and Jaccard come from the judge step, which is not part of this build. The gate takes them from an optional input file and reports `PENDING_DISCOVERY_SCORES` without it. The detection side is always computed.
4. Percentile: linear interpolation between order statistics (the numpy default).
5. Audit: a fresh `random.Random(20260311)` per stratum; presentation order shuffled with the same seed; agreement means (1) intended code confirmed by the reviewer, (2) reviewer set equals the oracle set, (3) reviewer set empty.
6. Cost per true failure: generation tokens pro rata by slots used (all-runs total also reported), plus agent tokens of the scenarios in the budget.
7. Resumption: runs are append-only and keyed; a rerun skips completed keys. Curtailment is recomputed from the log, so it is deterministic.
8. The >10% degenerate-reply gate is evaluated at the end of each phase (drift, detection), as in `engine.degenerate_gate`.
9. A drift verdict of `POTENTIALLY_INVALID` stops the detection runner unless `--acknowledge-potentially-invalid` is given (2.15 requires the user to be told first). A served model that cannot be established is recorded as `UNESTABLISHED`, not as the same model.
